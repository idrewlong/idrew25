# Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Sanity-backed blog to idrewlong.com, with externally-published articles kept as distinct "features" surfaced on both the homepage and `/blog/`.

**Architecture:** Vue pages never query Sanity. Every read goes through a Nitro server route that fetches via GROQ, renders Portable Text to an HTML string, and highlights code with Shiki. Pages consume plain JSON via `useFetch`. This keeps Shiki and the Portable Text renderer out of the client bundle, and makes draft preview the same code path with one flag changed.

**Tech Stack:** Nuxt 4.5, Vue 3.5, Tailwind v4 (`@tailwindcss/vite`), Sanity (`@sanity/client` v8), `@portabletext/to-html` v6, Shiki v4, Vitest, deployed on Vercel with ISR.

**Spec:** `docs/superpowers/specs/2026-09-20-blog-design.md`

## Global Constraints

- **Nuxt 4 `app/` directory.** Components live in `app/components/`, pages in `app/pages/`. Server code lives in `server/` at the repo root, NOT under `app/`.
- **Tailwind v4.** No `tailwind.config.js`. Utilities are generated by scanning source files; a class name that exists only in CMS data will never be generated. Never store Tailwind class strings in Sanity.
- **`site.trailingSlash: true`** is set in `nuxt.config.ts`. Every blog URL carries a trailing slash: `/blog/`, `/blog/my-post/`.
- **Indentation: tabs for all new files.** The repo is mixed — `Header.vue`, `app/pages/index.vue` and `app.vue` use tabs; `contact/index.vue` and `Articles.vue` use two spaces. When editing an existing file, match that file. When creating a new one, use tabs.
- **Date formatting lives in `app/utils/formatPostDate.ts`** and is auto-imported. Never redefine it in a component.
- **Existing visual language, do not invent one:** stone palette, `orange-500` accent, `font-serif italic` headings. Section labels are always `text-[10px] font-bold tracking-[0.25em] uppercase text-stone-400` followed by a `flex-1 h-px bg-stone-200` rule. Copy the pattern from `app/components/Articles.vue:4-8`.
- **Server utils must not use Nuxt auto-imports.** Pure functions in `server/utils/` take config as parameters so they are unit-testable outside the Nitro runtime. Route handlers call `useRuntimeConfig()` and pass values down.
- **No secrets in `runtimeConfig.public`.** All Sanity values are server-only. The one public value is the pre-existing `web3formsAccessKey`.
- **Commit after every task.** Do not batch commits across tasks.

## Deviation from spec — read before starting

The spec states automated tests are out of scope. This plan adds Vitest (Task 1) and tests the server data layer only: query building, Portable Text rendering, Shiki highlighting, and client configuration. Pages and components are verified manually, as the spec describes.

Rationale: the data layer is pure, dependency-light logic where failures are silent and expensive — a wrong GROQ projection produces `undefined` fields rather than an error. UI problems, by contrast, are obvious the moment you look at the page.

If you want the spec's original scope honoured exactly, delete Task 1 and drop every "write the failing test" step; the remaining implementation steps stand on their own.

`server/utils/sanity.ts`:

```ts
import { createClient, type SanityClient } from '@sanity/client';

export interface SanityConfig {
	projectId: string;
	dataset: string;
	apiVersion: string;
	readToken?: string;
}

export function createSanityClient(
	config: SanityConfig,
	opts: { preview?: boolean } = {}
): SanityClient {
	const preview = opts.preview === true;

	if (preview && !config.readToken) {
		throw new Error(
			'Preview mode requires SANITY_READ_TOKEN to be set. Without it, drafts cannot be read.'
		);
	}

	return createClient({
		projectId: config.projectId,
		dataset: config.dataset,
		apiVersion: config.apiVersion,
		// The CDN serves cached published content and cannot see drafts.
		useCdn: !preview,
		token: preview ? config.readToken : undefined,
		perspective: preview ? 'drafts' : 'published',
	});
}
```

- [ ] **Step 4: Write the renderer**

**Security note — this differs from a naive implementation on purpose.** Link hrefs
are classified by resolving them against `SITE_ORIGIN`, not by pattern-matching the
raw string. A browser resolves every href against the page URL, so `new URL(href)`
with no base tests something the browser never does: `//evil.com/x`, `/\evil.com`
and `\\evil.com` all resolve off-site while looking like same-site paths. External
links emit the RESOLVED absolute URL so an off-site link cannot be disguised as a
relative one, and any scheme that is not http/https/mailto renders as inert text with
no href at all. Do not replace this with prefix checks.


`server/utils/renderBody.ts`:

```ts
import { toHTML, type PortableTextComponents } from '@portabletext/to-html';
import { createHighlighter, type Highlighter } from 'shiki';

const THEME = 'github-light';

// Every language the Studio offers. Anything else falls back to plain text.
const LANGS = [
	'typescript',
	'javascript',
	'vue',
	'html',
	'css',
	'bash',
	'json',
	'python',
];

// Shiki's initialisation is expensive, so the instance is created once per
// server process and reused across requests.
let highlighterPromise: Promise<Highlighter> | null = null;

function getHighlighter(): Promise<Highlighter> {
	if (!highlighterPromise) {
		highlighterPromise = createHighlighter({
			themes: [THEME],
			langs: LANGS,
		});
	}
	return highlighterPromise;
}

function escapeHtml(value: string): string {
	return value
		.replace(/&/g, '&amp;')
		.replace(/</g, '&lt;')
		.replace(/>/g, '&gt;')
		.replace(/"/g, '&quot;');
}

export function slugifyHeading(text: string): string {
	return text
		.toLowerCase()
		.trim()
		.replace(/[^a-z0-9\s-]/g, '')
		.replace(/\s+/g, '-')
		.replace(/-+/g, '-');
}

function headingText(value: { children?: Array<{ text?: string }> }): string {
	return (value?.children ?? []).map((child) => child?.text ?? '').join('');
}

function plainCodeBlock(code: string): string {
	return `<pre class="shiki plain"><code>${escapeHtml(code)}</code></pre>`;
}

const SITE_ORIGIN = 'https://www.idrewlong.com';
const SITE_HOSTNAMES = new Set(['idrewlong.com', 'www.idrewlong.com']);

interface HrefClassification {
	safe: boolean;
	external: boolean;
	href: string;
}

// A browser resolves every href against the PAGE's URL, so testing the raw
// string (prefix checks, `new URL(href)` with no base) checks something the
// browser never does — WHATWG's URL parser normalises backslashes to
// forward slashes for special schemes, so spellings like `/\evil.com` or
// `\\evil.com` resolve off-site even though they don't look like it as a
// string. Resolving against the site's own origin, the way a browser
// would, is the only classification that agrees with what actually
// renders. `SITE_ORIGIN` doubles as the base for that resolution.
function classifyHref(href: string): HrefClassification {
	let resolved: URL;
	try {
		resolved = new URL(href, SITE_ORIGIN);
	} catch {
		return { safe: false, external: false, href };
	}
	if (resolved.protocol === 'mailto:') {
		return { safe: true, external: false, href };
	}
	if (resolved.protocol !== 'http:' && resolved.protocol !== 'https:') {
		// javascript:, data:, vbscript:, etc. — still rejected, since they
		// parse to their own scheme even with a base supplied.
		return { safe: false, external: false, href };
	}
	const external = !SITE_HOSTNAMES.has(resolved.hostname);
	// Internal links keep the author's original (possibly relative) href.
	// External links emit the resolved absolute URL, so a link that
	// actually leaves the site says so in the markup rather than reading
	// like a same-site path.
	return { safe: true, external, href: external ? resolved.href : href };
}

const components: PortableTextComponents = {
	block: {
		normal: ({ children }) => `<p>${children}</p>`,
		h2: ({ children, value }) =>
			`<h2 id="${slugifyHeading(headingText(value))}">${children}</h2>`,
		h3: ({ children, value }) =>
			`<h3 id="${slugifyHeading(headingText(value))}">${children}</h3>`,
		blockquote: ({ children }) => `<blockquote>${children}</blockquote>`,
	},
	list: {
		bullet: ({ children }) => `<ul>${children}</ul>`,
		number: ({ children }) => `<ol>${children}</ol>`,
	},
	listItem: {
		bullet: ({ children }) => `<li>${children}</li>`,
		number: ({ children }) => `<li>${children}</li>`,
	},
	marks: {
		code: ({ children }) => `<code class="inline-code">${children}</code>`,
		link: ({ children, value }) => {
			const classification = classifyHref(String(value?.href ?? ''));
			if (!classification.safe) return `<a>${children}</a>`;
			const attrs = classification.external
				? ' target="_blank" rel="noopener noreferrer"'
				: '';
			return `<a href="${escapeHtml(classification.href)}"${attrs}>${children}</a>`;
		},
	},
	types: {
		code: ({ value }) => {
			const filename = value?.filename
				? `<figcaption class="code-filename">${escapeHtml(String(value.filename))}</figcaption>`
				: '';
			const body =
				value?.html ?? plainCodeBlock(String(value?.code ?? ''));
			return `<figure class="code-block">${filename}${body}</figure>`;
		},
		image: ({ value }) => {
			if (!value?.url) return '';
			const alt = escapeHtml(String(value.alt ?? ''));
			const caption = value.caption
				? `<figcaption>${escapeHtml(String(value.caption))}</figcaption>`
				: '';
			const dims =
				value.width && value.height
					? ` width="${value.width}" height="${value.height}"`
					: '';
			const src = `${value.url}?w=1400&fm=webp&q=80`;
			return `<figure class="body-image"><img src="${escapeHtml(src)}" alt="${alt}"${dims} loading="lazy" decoding="async" />${caption}</figure>`;
		},
	},
};

// toHTML is synchronous but Shiki's setup is not, so code blocks are
// highlighted into a `html` field first and the component reads that.
async function withHighlightedCode(
	blocks: Array<Record<string, unknown>>
): Promise<Array<Record<string, unknown>>> {
	if (!blocks.some((b) => b?._type === 'code')) return blocks;

	const highlighter = await getHighlighter();

	return blocks.map((b) => {
		if (b?._type !== 'code') return b;
		const code = typeof b.code === 'string' ? b.code : '';
		const lang = LANGS.includes(String(b.language)) ? String(b.language) : null;
		const html = lang
			? highlighter.codeToHtml(code, { lang, theme: THEME })
			: plainCodeBlock(code);
		return { ...b, html };
	});
}

export async function renderBody(blocks: unknown): Promise<string> {
	if (!Array.isArray(blocks) || blocks.length === 0) return '';
	const prepared = await withHighlightedCode(
		blocks as Array<Record<string, unknown>>
	);
	return toHTML(prepared as never, { components });
}
```

```ts
const { $gsap } = useNuxtApp();
const pageRoot = ref<HTMLElement | null>(null);

onMounted(() => {
	nextTick(() => {
		if (!pageRoot.value) return;

		// Respect the OS setting rather than animating regardless.
		if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
			return;
		}

		const cards = pageRoot.value.querySelectorAll(
			'.post-card, .feature-card'
		);
		if (!cards.length) return;

		$gsap.set(cards, { opacity: 0, y: 40 });
		$gsap.to(cards, {
			opacity: 1,
			y: 0,
			duration: 0.7,
			ease: 'expo.out',
			stagger: 0.08,
			clearProps: 'transform',
			scrollTrigger: {
				trigger: pageRoot.value,
				start: 'top 90%',
				toggleActions: 'play none none none',
			},
		});
	});
});
```

This matches the timing and easing already used in `FeaturedWriting.vue`, so
the two sections feel like one site. The selectors target the card classes from
Steps 1 and 2, so they must stay as named.

- [ ] **Step 1: Write the source route**

`server/api/__sitemap__/urls.ts`:

```ts
import type { SanityConfig } from '../../utils/sanity';

interface PostSlugRow {
	slug: string;
	lastmod: string;
}

// defineSitemapEventHandler is provided by @nuxtjs/sitemap, which ships as
// part of @nuxtjs/seo.
export default defineSitemapEventHandler(async () => {
	const runtime = useRuntimeConfig();
	const client = createSanityClient(runtime.sanity as SanityConfig);

	const rows: PostSlugRow[] = (await client.fetch(POST_SLUGS_QUERY)) ?? [];

	// Trailing slashes to match site.trailingSlash: true.
	return rows.map((row) => ({
		loc: `/blog/${row.slug}/`,
		lastmod: row.lastmod,
	}));
});
```

## Task 12: Draft preview

**Files:**
- Create: `server/routes/preview/enable.get.ts`, `server/routes/preview/disable.get.ts`, `app/pages/preview/blog/[slug].vue`

**Interfaces:**
- Consumes: `PREVIEW_COOKIE` (Task 6), `runtime.previewSecret` (Task 6 step 7), the `/preview/**` route rule (Task 6 step 8)
- Produces: `/preview/enable?secret=&slug=`, `/preview/disable`, and the uncached route `/preview/blog/:slug/`

Drafts render under their own route namespace rather than `/blog/`. A cookie does not vary Vercel's ISR cache key, so sharing the `/blog/` path would either serve you a stale published copy or risk caching a draft and serving it to the public.

- [ ] **Step 1: Write the enable route**

`server/routes/preview/enable.get.ts`:

```ts
export default defineEventHandler(async (event) => {
	const runtime = useRuntimeConfig();
	const { secret, slug } = getQuery(event);

	if (!runtime.previewSecret || secret !== runtime.previewSecret) {
		throw createError({
			statusCode: 401,
			statusMessage: 'Invalid preview secret',
		});
	}

	if (typeof slug !== 'string' || slug.length === 0) {
		throw createError({ statusCode: 400, statusMessage: 'Missing slug' });
	}

	setCookie(event, PREVIEW_COOKIE, '1', {
		httpOnly: true,
		sameSite: 'lax',
		path: '/',
		secure: !import.meta.dev,
		maxAge: 60 * 60,
	});

	return sendRedirect(event, `/preview/blog/${slug}/`);
});
```

The cookie expires after an hour on its own. A preview session that never ends is a preview session you forget you are in.

- [ ] **Step 2: Write the disable route**

`server/routes/preview/disable.get.ts`:

```ts
export default defineEventHandler(async (event) => {
	deleteCookie(event, PREVIEW_COOKIE, { path: '/' });
	return sendRedirect(event, '/blog/');
});
```
